# style6-v2 Amazon 强信息转化图组系统

## 定位与 A/B 对照契约

`style6-v2` 用于 Amazon 等以快速理解、减少下单疑虑、信息证据充分为目标的详情图。它不是把产品与所有配件排成一列；它把一套图片设计为从“我买到什么”到“为什么适合我”再到“如何确认”的决策路径。

与 `style6-v3` 做对照测试时，必须锁定同一份产品事实、同一组产品身份参考、同一输出比例、同一目标市场/语言、同一文案事实、同一图片类型和同一安全区。只允许改变视觉导演策略。

## 绝对事实边界

- 用户提供的产品图片是外形、颜色、材质、结构、接口、包装和配件的唯一事实来源。
- 只有在包装清单或实拍明确证明时，才可把多个组件同时作为“套装”呈现；多张参考图不代表产品有多个实例。
- 不可虚构数量、尺寸、材料、内部结构、认证、兼容性、性能、效果、人物需求或使用结果。
- 每张图保留顶右角自然 logo 安全区；不画占位框、边框、文字、图标或产品。

## 产品参考角色

生成每张图前，先从上传图中选 1--4 张最相关的图，并在内部标记角色：

- `identity-anchor`：最能锁定单品整体外形的主参考。
- `view-proof`：证明侧面、背面、接口或另一角度的参考。
- `set-proof`：证明包装、组件和真实套装关系的参考。
- `detail-proof`：证明纹理、按钮、接口或结构细节的参考。

只把本镜头需要的参考传给 Image Gen。多张参考用于校准同一个真实产品，除非 `set-proof` 证明是实际包装内容，否则不得把它们渲染成整齐重复的多个产品。

## 先做套图 Coverage Matrix

在写每张 prompt 前，建立并展示一张内部镜头表。被选中的图片类型必须映射到不同的产品呈现方式：

| 类型 | 主要产品呈现 | 决策问题 |
| --- | --- | --- |
| Hero | 已验证的完整套装或主产品总览 | 我买到什么？ |
| Selling | 单品主视觉加可验证卖点证据 | 它解决什么问题？ |
| CoreA | 核心使用场景 A | 为什么适合我的主要情境？ |
| CoreB | 与 CoreA 不同的人群、空间或时段 | 还有什么高价值使用路径？ |
| Feature | 可见结构或工作步骤的近景 | 它怎样工作？ |
| Specs | 单品多视角、尺寸或包装事实 | 外形和规格是否符合预期？ |
| Value | 单品与已验证价值模块 | 为什么值得选择？ |
| Compare | 单品与无品牌通用替代物 | 有何可证明差异？ |
| Lifestyle | 自然使用瞬间 | 使用后的生活体验是什么？ |
| Closing | 单品或已验证套装的收束视觉 | 我是否已准备好选择它？ |
| Guide | 真实操作的 2--4 步 | 我怎样开始使用？ |

如果用户只选少量类型，优先保证“套装/总览、单品特写、多角度或功能、场景”四种表达不重复。每张图至少在产品形态、景别、机位、背景、信息主导和光线中的四项与前图不同。

## 画面语法：信息清晰，但不做产品全排列

每张图按以下层级设计，缺少真实证据的层必须省略：

1. `环境层`：白灰、浅暖灰或深蓝渐变棚景；场景图只使用确认的使用语境。
2. `主体层`：一个主产品或经确认的完整套装；主件始终最清楚、最完整。
3. `证据层`：单个局部放大、第二视角、真实配件或步骤，作为叙事证据，而非装饰性堆叠。
4. `UI 层`：短标题、图标、规格药丸、编号、细引线、卡片或底部条；信息层级清楚、留白充足。
5. `渲染层`：真实软阴影、干净反射、蓝白轮廓光、有限金色强调线；所有光效只服务于可见事实。

主产品通常占画面 45%--68%。只有单品极简特写可超过该范围；任何 UI、图标、文字、放大镜或配件都不得遮挡主产品轮廓。

## 动态镜头配方

每张图必须先形成下列配方，再将其展开为最终 Image Gen 指令；不要直接套用相同句子。

```text
镜头目标：<本图要消除的购买疑虑>
产品形态：<单品 / 已验证套装 / 局部细节 / 使用中>
真实证据：<仅能从产品资料确认的组件、结构、卖点、规格>
叙事瞬间：<基于已确认使用场景的具体瞬间>
镜头：<景别、角度、产品占比、前中后景>
图层：<环境层 → 主体层 → 证据层 → UI 层 → 渲染层>
UI：<标题层级、图标/连线/卡片，以及哪些内容必须省略>
光效：<真实光源、阴影、轮廓光、少量材质强调>
文案：<仅使用已确认事实，目标语言简短可读>
避免：<本图不允许的重复构图、虚构物、过度特效>
```

最终 prompt 必须明确要求：保留真实产品比例与细节；所有可见文字使用 `{language}`；只使用 `{headline}`、`{subheadline}`、`{selling_points}`、`{specs}`、`{accessories}`、`{scenes}` 和 `{use_context}` 中已提供的内容；没有事实就留白，不用猜测填充。

## style6-v2 分镜指令

### Hero — 已验证套装/总览

- 有真实包装清单时：用 45° 主件加克制的层级式组件关系展示，不做横向全排列；主件居中偏右，组件以“包含关系”围绕，而非平铺。
- 没有套装事实时：只展示一个主产品，使用“完整准备就绪”价值标题，禁止暗示多件。
- 左侧放一条大标题与 3--5 条短证据；下方最多一条真实配件/场景/参数信息带。白灰棚景、深蓝模块、少量金色重点。

### Selling — 单品价值证明

- 用单一产品的中近景作为绝对主角，选择与 Hero 不同的机位。
- 只用一个局部证据窗口或一个可验证结果情境，讲清“卖点 → 可见依据 → 使用价值”。
- UI 是一张主卖点卡加 2--3 个线性图标；不要复用 Hero 的组件矩阵。

### CoreA — 主要使用路径

- 以 `{scenes}` 中最典型、最具体的场景为主，产品处于真实使用动作或准备动作中。
- 前景是产品和手部/环境交互，中景给出被确认的使用空间，背景柔焦；人物仅为情境服务且不成为代言人。
- 用短标题和一条低干扰的场景收益条，不把场景做成信息面板。

### CoreB — 第二条高价值路径

- 必须与 CoreA 改变至少两项：场景、人群、时间、产品角度、动作或环境色温。
- 采用另一种使用路径，例如收纳、携带、准备、清洁或另一房间；只有资料明确支持时才使用。
- 主产品保持可辨识，UI 改为 2--3 个小型注释，不重复 CoreA 的主标题节奏。

### Feature — 结构/功能近景

- 用已确认的接口、按键、纹理、可见部件或操作步骤做微距焦点；不可绘制不存在的爆炸结构、X 光透视或内部零件。
- 主图为局部近景，辅以一个较小的完整产品轮廓作方位提示；最多两条细引线。
- 采用蓝白技术光、干净阴影和小面积金色强调，形成“证据板”而非“蓝图幻觉”。

### Specs — 多视角/规格证明

- 按资料可用性选择正侧背三视图、一个尺寸视图，或包装清单视图；不要求不存在的角度。
- 单品可使用轻量旋转台或 2--3 个不同视角，不可复制成多件产品。
- 尺寸线、参数药丸和包装事实只有在真实数值存在时显示；无数值时使用“设计细节/包装内容”文字，不编数字。

### Value — 可选择理由

- 以单品 45° 视图为核心，围绕 3 个已验证的价值点形成不对称信息轨道。
- 价值点使用图标、短标签、材质小窗或使用情境缩略证据，避免又一次“整套产品排开”。
- 使用深蓝至白灰的分层背景和有节制的金色标记，营造高转化但不拥挤的阅读路径。

### Compare — 可证明差异

- 左右比较只针对已证实的属性；对照品必须是无品牌、抽象且通用的物体。
- 客户产品要显示真实外形与结构；对照品不可模仿竞品设计、商标或可识别包装。
- 使用简洁对勾/横线、两到四行短对比，不用贬损、绝对词或未经证实的性能结论。

### Lifestyle — 生活融入

- 用自然光或暖冷平衡的真实环境，聚焦用户获得的日常便利或舒适感。
- 产品可在前景、中景或手中，但需保持明确可辨；只允许一个小型半透明卖点卡或底部短句。
- 不使用密集参数、组件矩阵或悬浮信息板，让这一张成为整套图的呼吸位。

### Closing — 决策收束

- 以主产品或真实套装的干净英雄镜头收束，可用更深的渐变背景、克制光束和一个可信的价值总结。
- 文案为品牌/产品名（仅已提供时）与 1 条事实性收束语；不写虚构奖项、倒计时、折扣或平台标识。
- 不复用 Hero 的产品角度、组件布局或底部卡片结构。

### Guide — 开始使用

- 基于可确认的实际操作，做 2--4 个顺序步骤；每步必须清楚展示手、产品或已确认组件的真实关系。
- 使用编号、短动作词和连续视觉动线；禁止创建需要猜测的安装、充电、清洁或维护步骤。
- 画面以单一干净背景为主，图层重点是步骤证据，不使用生活方式场景。

## A/B 验收

- 信息在 3 秒内可读：主产品、核心价值、真实套装内容或场景意图清楚。
- 不同图片之间没有重复的产品全排列、同一正面机位或同一 UI 模块组合。
- 每张图包含至少一个与该镜头目标相关的真实证据；没有依据的元素宁可省略。
- 与 style6-v3 对比时，v2 应明显更模块化、更直接、更适合快速扫描，但仍有景别与场景变化。
